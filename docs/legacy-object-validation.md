# Serialized model compatibility validation

Validation date: 2026-09-20.

The audit creates fitted objects using archived quickNet source in a fresh R
process, writes them with `saveRDS()`, and reads them in a separate process
running the current source. The main evidence uses actual historical
constructors and their complete returned objects. It does not simulate history
by deleting metadata from a newly fitted object.

## Source and runtime coverage

Historical sources are fixed to:

- `29a414bafa5ff018b6489bc46e5d8ffcb8fb68c7`;
- `72666a3fb587df40db0ffc89d2bff5ec2dbcb21c`.

The working source is also checked through independent creation and consumption
processes. The six designs below were run for both historical revisions and
the current source, giving 18 cases per runtime.

| Runtime | R | bootnet | qgraph | IsingFit | mgm | glmnet | Matrix | Result |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Linux | 4.5.3 | 1.9.1 | 1.10.1 | 0.4 | 1.2.15 | 5.0 | 1.7.4 | 18/18 passed |
| Native Windows | 4.5.0 | 1.8 | 1.9.8 | 0.4 | 1.2.15 | 4.1.10 | 1.7.4 | 18/18 passed |

Each row creates and consumes objects with the same backend versions. It tests
quickNet revision compatibility and independent-session serialization. It does
not require numerical invariance across backend upgrades; those upgrades may
legitimately change estimates.

| Design | Controls and evidence checked |
| --- | --- |
| EBICglasso | Historical actual Pearson estimation despite recorded `cor_method="spearman"`; saved bootnet estimator defaults and gamma; current explicit gamma 0.17 and 40 lambdas. |
| EBICglasso with missing observations | Historical `missing="none"` allowed the original bootnet pairwise rule; four missing observations remain in the input. |
| Ising | `AND=FALSE`; historical gamma 0.5 and 0.25 are retained according to the actual object. |
| MGM | Actual `lambdaSel="EBIC"`, `ruleReg="OR"`, types, levels, and fitted gamma; current explicit gamma 0.13. |
| Partial correlation | Spearman correlation and the historical positive-definite repair policy. |
| CLPN | Three waves and three nodes; alpha 0.6, four folds, `lambda.min`, seed 703; historical per-wave preprocessing versus the glmnet `standardize` argument; current explicit preprocessing and `intercept=FALSE`. |

All inputs are anonymous data generated by a fixed-seed script. For each design,
the historical constructor also estimates a fixed row resample and saves that
result as the numerical oracle. Current refitting is compared with this oracle,
not merely with another call through a current quickNet wrapper. The largest
absolute difference was `1.3878e-16` in both runtimes; all current-object
differences were zero.

## Current compatibility behavior

- EBIC settings are recovered from the estimator function and supplied
  arguments saved inside the bootnet object. Saved function defaults preserve
  the original correlation, missing-data, sample-size, lambda-path, transform,
  and refitting settings. Explicit backend arguments take precedence over
  saved defaults. Current installed defaults do not replace this evidence.
- Reports use effective backend evidence. They state the correlation actually
  used by historical EBIC objects and the effective pairwise missing-data rule.
  Ising and MGM reports omit an inapplicable correlation-method field. Legacy
  CLPN reports distinguish data preprocessing from glmnet standardization.
  Reporting does not rewrite the user's saved object.
- An EBIC object without recoverable correlation provenance cannot be refitted
  silently. The report identifies the missing value as `unknown (not recorded)`
  and refitting stops with an explanatory error. The same distinction applies
  to an unknown historical EBIC missing-data rule, MGM selection method, Ising
  AND rule, and CLPN preprocessing or glmnet standardization setting.
- Stability and network comparison obtain controls from the same refitting
  resolver. Existing gamma recovery continues to prefer the fitted backend
  over stale wrapper metadata.

The missing-data case demonstrates a concrete compatibility failure: the prior
refitting resolver forwarded historical `missing="none"` to the current
constructor, which rejected the original incomplete input with
`Missing data detected and missing = 'stop'`. Recovering the saved bootnet
pairwise rule makes the historical resample reproducible.

## Checks and reproducibility

Every integration case covers `readRDS()`, printing, summary, qgraph-backed
plotting, reporting, refitting, finite networks, and a second save/read cycle.
Cross-sectional cases additionally exercise the actual public `NetCompare()`
and `Stability()` functions and compare their unchanged original networks.
Their two permutations and three bootstrap repetitions are execution and
control-preservation checks; they do not validate the precision of p-values,
confidence intervals, or stability coefficients. Backend warnings are retained
in the result manifests.

Run from the package directory:

```sh
Rscript --vanilla tools/validate-legacy-objects.R
```

The script writes archived sources, complete per-model objects, old-source
refitting oracles, logs, PDF output, backend versions, and validation results to
`../output/audit/legacy-objects/{29a414b,72666a3,current}/`. The native Windows
audit artifacts are retained separately under
`../output/audit/legacy-objects-windows/`. The `--create SOURCE OUTPUT LABEL`
and `--consume SOURCE OUTPUT` modes allow each phase to run independently.

`tests/testthat/fixtures/legacy-29a414b.rds` and
`tests/testthat/fixtures/legacy-72666a3.rds` bundle the complete original Linux
objects, resample oracles, and creation manifests for fast regression tests.
Only the bundle container is serialized using R format version 2 to avoid
raising the package's minimum R version solely for a test fixture. Individual
objects in the integration audit use serialization format version 3. No model
fields are removed from the bundles. To rebuild a bundle after the integration
script completes:

```r
for (revision in c("29a414b", "72666a3")) {
  directory <- file.path("..", "output", "audit", "legacy-objects", revision)
  manifest <- readRDS(file.path(directory, "manifest.rds"))
  manifest$source_commit <- readLines(file.path(directory, "source-commit.txt"))
  cases <- names(manifest$cases)
  fits <- setNames(lapply(cases, function(x)
    readRDS(file.path(directory, "objects", paste0(x, ".rds")))), cases)
  oracles <- setNames(lapply(cases, function(x)
    readRDS(file.path(directory, "objects", paste0(x, "-oracle.rds")))), cases)
  saveRDS(list(manifest = manifest, fits = fits, oracles = oracles),
    file.path("tests", "testthat", "fixtures", paste0("legacy-", revision, ".rds")),
    compress = "xz", version = 2)
}
```

`test-serialized-compatibility.R` verifies those real fixtures, effective
reports, layout and node labels, saved control recovery, gamma, and numerical
refitting when the creation backend versions match. Separate boundary tests
deliberately remove provenance to verify explicit unknown values and errors;
these are not counted as historical-object evidence. This coverage establishes
compatibility for the recorded revisions and model designs, not every object
schema or backend version ever released.

The dedicated suite passed 230 assertions under the recorded Linux environment.
The final complete Linux and Windows package checks, and 18 Windows-to-Linux
object checks, are recorded in the [platform audit](platform-compatibility-validation.md).
