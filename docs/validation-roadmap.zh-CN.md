## 核验任务与验收标准

本节保留制定计划时的清单。下列“依据”及行号对应当时源码，不描述修复后的当前行为；执行结果以上方记录为准。

### A. 结果的数学含义与后端提取：最高优先级

**目的：**确认输出矩阵、边表、中心性、图形和报告对应同一组参数。

1. 用已知单向关系的数据，例如仅有 `A(t-1) -> B(t)`，验证 CLPN、mlVAR、graphicalVAR、psychonetrics 和动态 MGM 的方向、正负号、自回归项与滞后层。
2. 扩展潜变量、RI-CLPM、panel VAR 和 MetaNet 的真实后端逐项对照：参数矩阵、标准化方式、网络层、拟合指标和样本量。现有 MetaNet 测试主要覆盖对象结构及输出字段，应补独立数值证据。
3. 用 3–5 节点手算网络核对 strength、expected influence、桥指标、孤立节点、负边、自环、归一化和不同模块大小。
4. 核对绘图阈值、缓存 qgraph 对象与原始拟合矩阵之间的关系，确认显示设置不会无说明地改变用于统计的网络。

**验收：**预先写明每一层的行列方向、单位和参数定义；手算、直接后端、quickNet 的对应结果在预定容差内一致；随机估计同时核查收敛状态。容差根据运算类型、参数尺度和优化精度制定，不以一个统一数值覆盖全部模型。

**依据：**`R/longitudinal.R:792`；`tests/testthat/test-regressions.R:1`；`tests/testthat/test-meta-net.R:1`；`R/Centrality.R`；`R/Bridge.R`。

### B. 数据对齐、时间边界和分析样本：最高优先级

1. 列重排、重命名、非字母排序标签、中文标签、研究间矩阵顺序不同、配对样本顺序不同。
2. 在已提供完整时间索引时，打乱输入行后结果应保持一致；未提供时间索引时，明确行顺序的含义，不要求任意打乱后仍相同。
3. 检查跨受试者、跨日、漏测、时间间隔不等及多滞后情形是否形成了正确的观测对。省略 day/beep、只给其中一个以及同时提供时分别检查。
4. 缺失机制与缺失处理交叉核查：传给后端的数据、实际有效样本、不同波次/节点的样本数，以及报告是否一致。
5. 扩展类别稀疏、类别消失、常数列、接近共线、非正定矩阵和不同量纲场景；对不支持的情况明确拒绝或说明。

**验收：**适用的名称/顺序变换满足不变性；时间配对可以用独立构造的索引表核对；每次删行或样本减少均可追溯；不支持的数据结构不会以正常结果形式继续。

**依据：**`R/input_specs.R:434`、`:639`；`R/longitudinal.R:219`、`:379`；`R/meta.R`。

### C. 置换和重抽样的统计表现：最高优先级

1. **NCT：**同一总体网络下模拟独立/配对、等/不等样本量、稀疏二分类数据；核验全局、逐边和中心性检验的误拒率及多重校正。补充可以穷举的小样本置换基准。
2. **MTD：**用两条彼此独立但各自有自相关的序列检验零假设表现；比较保留时间依赖的候选零分布。先评估适用条件，再决定是否调整方法。
3. **Bootstrap：**横断面与受试者整簇重抽样分别验证；评估区间覆盖、符号/选择稳定性，以及正则化零边、少受试者、常量节点和失败重拟合的影响。
4. **统计量解释：**区分自有 case-drop 摘要与 bootnet CS 系数；明确 netCor 的节点置换零假设，以及它与总体网络差异检验的关系。

**验收：**先确定检验目标和适用前提，再报告误拒率、覆盖率、失败率及 Monte Carlo 误差。性能偏差需区分实现问题与源方法限制，不能为了通过测试改写结论或隐去失败样本。

**依据：**`R/NCT_gl.R:308` 明确提示配对数据方法尚未验证，`:317` 对稀疏二分类采用可拟合分割的拒绝抽样；`R/MTD.No.Smooth.Test.R:62` 打乱第二条序列；纵向稳定性已有整簇抽样，但部分测试采用 `nboot=1`，证明的是流程可运行。

### D. 收敛、失败和不确定性报告：最高优先级

1. 构造不收敛、奇异解、缺失网络层、部分/全部 bootstrap 失败的可重复实例。
2. 核查“后端返回对象”和“估计有效”的区分；检查优化状态、非有限参数及不可用拟合指标是否正确传到报告。
3. 已有失败次数记录应核对分母和解释；评估补充失败原因类别、代表性错误和实际成功次数的必要性。
4. 检查失败后随机状态、工作进程和图形设备的清理；已有 NIRA 清理测试作为基线。

**验收：**失败不能变成零效应或成功拟合；请求/成功/失败次数一致；全失败清楚终止；报告足以定位失败原因；低成功率下的结果解释有明确边界。

**依据：**`R/longitudinal.R:859` 捕获异常后返回 NULL，已有失败计数但该处不保留异常原因；其他模型按共享路径检查。

### E. 虚拟干预精度与排序可靠性：高优先级

1. **NIRA 采样：**强正关联、正负混合、极端阈值、近并列目标；小网络枚举全部状态，比较多个迭代预算、种子下的概率、均值、效应量和排名误差。
2. **NIRA 推断：**评估调节前置检验的误报/检出、模拟分布置换检验的校准，以及调节 bootstrap 的失败影响。图表应持续区分固定网络的模拟不确定性与原始样本的估计不确定性。
3. **SymPerturb 独立公式：**用条件高斯推导及数值积分对照均值、协方差和有界正态期望；覆盖近奇异、零方差、负边抵消、全零拓扑。检查零剂量还原、协方差半正定、名称变换等性质；不强求负边网络中的效果总是正向或单调。
4. **排名/区间：**用独立生成的数据集评估重复抽样表现，包含并列、近并列、重抽样后退化数据和候选池变化。明确 top-k 在并列时的定义。
5. **序列搜索：**4–6 候选节点做独立穷举；充分宽的 beam 应达到相同目标值，窄 beam 记录近似损失。

**验收：**给出误差和稳定性随模拟预算变化的证据，列出已验证的适用范围；保留与论文/参考代码一致性的既有结果。数值一致性、统计表现和因果效果证据分别说明。

**依据：**`R/nira_simulation.R`；`tests/testthat/test-nira.R:188`、`:255`；`R/symperturb_core.R`；`R/symperturb_analysis.R`。

### F. 功效与样本量推荐的独立验证：高优先级

1. 核对正定化后实际网络的密度、边强度和报告值。
2. 区分给定一个真实网络的条件结果与跨网络结构的稳健性；增加多个网络种子、拓扑、弱边及模型类型。
3. 达标概率附 Monte Carlo 误差，并核对拟合失败计入分母的规则。
4. 推荐样本量得到后，用独立新模拟验证其达标概率和不确定性；检查候选范围边界、未达标及非单调结果。
5. 真实 Powerly 集成继续保留慢速验证；已有小规模运行只用于接口与结果提取检查。

**验收：**推荐值可复现、实际设计透明、边界与未达标情况不被报告为成功；恢复概率的含义与边假设检验 power 分别说明。

**依据：**`R/power.R:223`、`:433`、`:566`；`docs/backend-parameter-audit.md` 的小规模运行记录。

### G. 跨会话、跨平台与依赖版本：发布前完成

1. 从历史 commit 用合成数据生成真实旧 RDS 对象；在干净 R 会话中读取并运行 print/summary/report/plot 及适用的下游分析。当前通过删除元数据模拟旧对象的测试继续保留。
2. 新对象保存、退出、重启、读取后复核数值及参数来源。
3. Windows、Linux、macOS 建立安装与测试矩阵；固定验证基线和最新依赖分别运行。根据实测确定最低支持版本。
4. 特别监测 qgraph 内部白名单解析、psychonetrics/lavaan S4 字段及后端返回维度的变化。
5. 最小依赖与完整可选依赖环境分开检查；关键后端测试的意外跳过需可见。

**验收：**每个支持环境有检查结果和版本记录；保存对象可迁移或明确报错；依赖升级引起的接口变化能够被自动测试发现。

## 执行顺序与工作量控制

1. **第一阶段：明确目标并建立独立基准。**开展 A、B、D 的快速确定性核验，为 C、E、F 写好模拟设计；按后端和共享代码路径分组，避免机械复制 32 套测试。产出“模型/流程—独立证据—状态”的覆盖表。
2. **第二阶段：统计验证。**优先 C，其次 E、F。每个场景先做小规模试跑估算失败率和计算成本，再按所需精度确定重复次数。发布兼容性 G 可同时推进。
3. **第三阶段：固化与发行。**完成 G、H；把发现的实现问题加入日常回归测试，把方法限制写入说明；运行完整包检查并生成有版本标记的核验报告。

模拟明确区分外层独立数据集数、内部置换/重抽样数和采样迭代数。例如真实误拒率为 0.05 时，2000 个独立数据集对应 Monte Carlo 标准误约 0.0049，即 0.49 个百分点；这是设计精度示例，不是给所有场景统一规定 2000 次。重复次数、容差和成功判据应在观察最终结果前确定。

日常测试保留小型、确定性回归；完整后端集成定期运行；耗时的统计模拟单独保存设计、种子、原始结果、失败记录和汇总。正式结论按“已验证”“有条件支持”“证据不足”“已确认问题”分别记录。
